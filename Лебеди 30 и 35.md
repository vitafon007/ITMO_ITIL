## Лебедь 30. Потеря площадки терминала D

### Что случилось

Площадка с основной инфраструктурой сервиса потеряна: авария, оборудование и помещения повреждены, доступ закрыт надзором, возврат от нескольких недель. Часть железа уничтожена, часть нельзя забрать. Резервная площадка есть, но неполная, на меньшую нагрузку, актуальность давно не проверяли. Бизнес работает и ждёт сервис.

В нашем проекте: из строя вышел контур терминала D (багажное железо + часть инфраструктуры сервиса в этом терминале).

### Что делаем (не закрываем сервис)

1. Объявляем **аварийный режим** по терминалу D. Письменно авиакомпаниям: что недоступно, что даём в **урезанном режиме** (часть функций, меньшая ёмкость), ориентир по срокам.
2. За первые часы **проверяем резерв** (раз «давно не смотрели»): какие системы живы, какая ёмкость, чего нет.
3. Параллельно две ветки:
   - аварийная схема сейчас: данные рейсов с резервного контура «Синхрон» вне повреждённого зала; багаж вручную / упрощённо / часть рейсов на B/C где можно;
   - план возврата в D на недели (закуп/ремонт, согласование с надзором).
4. Не держим обещание «как было за 4 часа»: честно фиксируем целевое время выхода на урезанный режим.
5. Приоритет P1 (критический инцидент) сразу на владельца сервиса + Рексофт + вендор оборудования.

### Изменения SLA (лебедь 30)

| Пункт | Было (ПР1) | Стало |
| --- | --- | --- |
| Доступность полного сервиса в D | 99,9% / календарный месяц | В **аварийном режиме** цель 99,9% **не применяется**. Минуты аварии площадки учитываются отдельно, не как обычный простой |
| Исключения из доступности | форс-мажор, вина заказчика, ОрВД/DCS, плановые окна | + **авария площадки D с закрытием надзором** (потеря производственной площадки). Исключение действует только после объявления аварийного режима и при предоставлении урезанного режима |
| RTO (целевое время восстановления) | 4 ч до полного восстановления | Полное восстановление площадки D: **недели** (вне месячной цели доступности). **Выход на урезанный режим ≤ 8 ч**: объявили аварию → подняли согласованную схему (данные с резерва + багаж B/C или вручную) |
| Кредиты за полный простой | 10 / 25 / 50% месячного платежа | Пока аварийный режим объявлен и заказчик принимает урезанный: кредиты за «полный простой D» **не начисляются**. Если урезанный режим тоже сорвали: кредит **20%** месячного платежа за каждые начавшиеся сутки без него |
| Плановые окна | предупреждение ≥48 ч | На период восстановления D: предупреждение ≥**24 ч** |
| Эскалация P1 | 1-я → 2-я → владелец | При аварийном режиме: **сразу** владелец сервиса + подрядчик Рексофт + вендор оборудования; на руководство без ожидания 50% таймера |

## Лебедь 35. Заказчики, данные рейсов, техдолг

### Что случилось

За 3 месяца серия нарушений. Два крупнейших заказчика (Аэрофлот и S7) требуют пересмотр соглашения, выплату накопленных компенсаций и независимый аудит. Один направил претензию и остановил платежи. Корень: техдолг и нехватка людей (о чём предупреждали). Компенсации в полном объёме ударят по бюджету, из которого чинят причины. Другие клиенты просят разъяснений, отраслевое издание готовит материал.

Конкретно для сервиса: сбои выдачи данных по расписанию и рейсам («кто куда летает»).

Аэрофлот: базовый перевозчик Шереметьево. S7: второй крупный заказчик в сценарии работы (публичного факта постоянного базирования S7 в SVO нет).

### Что делаем (не спорим «это не мы»)

1. Признаём серию сбоев по каналу данных. Руководитель контура ведёт разбор инцидента (см. шаблон ниже), не списываем на джуна.
2. С Аэрофлотом и S7: **пересмотр SLA**, не разовый «заплатите всё». Реструктуризация накопленных кредитов (часть деньгами/зачётом, часть услугами/отсрочкой), согласие на независимый аудит, график закрытия техдолга.
3. Кто остановил платежи: возобновление платежей = подписанное **временное соглашение** на период исправления + еженедельный статус по метрикам данных.
4. Остальным авиакомпаниям: короткое разъяснение **до** публикации в СМИ (факты, меры, без пустых обещаний).
5. Бюджет кредитов режем потолком, чтобы не съесть фонд устранения причин (найм/усиление смены, доработка интеграций). План: **+2 инженера** интеграций «Синхрон» (оценка).

### Изменения SLA (лебедь 35)

| Пункт | Было (ПР1) | Стало |
| --- | --- | --- |
| Метрики | только доступность «полного сервиса» | + показатель **доступность канала данных рейса** (доля минут, когда заказчик получает актуальные оперативные данные по своим рейсам D) |
| Сбой только данных (багаж жив) | деградация без отдельного кредита | приоритет P2; кредиты за канал данных: ниже 99,5% → **5%**; ниже 99,0% → **10%**; ниже 98,0% → **20%** месячного платежа |
| Потолок компенсации | 50% за месяц за полный простой | + **потолок за квартал 30%** месячного платежа по накопленным претензиям (чтобы бюджет чинил причины). Свыше 30%: реструктуризация (отсрочка / зачёт услугами) по согласованию |
| Аудит | не было | Два крупнейших заказчика: право на **1 независимый аудит эксплуатации в год** за свой счёт или по согласованной смете |
| Пересмотр соглашения | раз в год или после крупного P1 | + триггер: **два крупнейших заказчика одновременно** требуют пересмотр → внеочередной пересмотр за **10 рабочих дней** |
| Обязательства поставщика | мониторинг, отчёт, эскалация | + дорожная карта техдолга (доступна двум крупнейшим заказчикам); еженедельный статус, пока действует временное соглашение; план усиления смены (+2 инженера интеграций) |

## Оба лебедя сразу

Оба события действуют вместе. Порядок:

1. **Сначала** поднять урезанный режим по лебедю 30 (иначе нечего обещать по данным и багажу).
2. **Параллельно** временное соглашение с Аэрофлотом и S7 по лебедю 35.
3. Исключение «авария площадки D» **не обнуляет** исторические долги по сбоям данных за прошлые 3 месяца: их закрываем реструктуризацией и потолком квартала, не фразой «у нас авария, всё списано».
4. Внешняя коммуникация одна линия: что с площадкой D, что с данными, какие меры и сроки. Внутри: разбор инцидента, без режима «делаем вид, что ничего не было».

## Разбор инцидента (шаблон для руководства и заказчиков)

Честно, от уровня руководителя контура, без формулировок вроде «нашли зону роста».

1. **Кто отвечает за разбор:** владелец сервиса терминала D (не линейный инженер).
2. **Что произошло:** факты по 30 и/или 35 без сглаживания.
3. **Почему поздно / почему накопилось:** например, резерв D не проверяли по расписанию; по данным: техдолг интеграций и дыры в смене, о которых уже писали наверх.
4. **Что уже сделали:** урезанный режим, коммуникации, временное соглашение, открытый инцидент.
5. **Что меняем в системе:** проверки резерва раз в квартал с актом; показатель канала данных; найм/усиление; дорожная карта техдолга.
6. **Рекомендации другим контурам:** не держать «непроверенный резерв»; не копить нарушения без пересмотра SLA.
7. **Что просим у бизнеса:** бюджет на людей и железо резерва; не требовать 100% кредита, если это убивает ремонт причин.
